# ASL Sign Language Recognition

A research project on isolated American Sign Language (ASL) word-level recognition using multimodal deep learning. The system combines visual appearance and body/hand pose information through two independent feature-extraction branches and a Transformer-based fusion module.

## Research Reference

The project follows the multimodal research direction described in:

Alkhoraif et al., *Ensemble transformer-based word-level sign language recognition with multi-modal input fusion*, Journal of Engineering Research, 14 (2026).

DOI: https://doi.org/10.1016/j.jer.2025.07.006

The implementation is research-oriented and does not claim an exact reproduction of the reference paper. Implementation choices and deviations are documented separately.

## Architecture

The system consists of three components:

1. **Appearance branch:** A Video Swin Transformer processes 16 RGB frames sampled from each video and resized to 224 × 224.
2. **Pose branch:** MediaPipe Holistic extracts body and hand landmarks. The landmarks are converted into a Landmark-to-Image (LTI) representation and processed by a Swin Transformer.
3. **Feature fusion:** The two 1,024-dimensional feature vectors are concatenated and passed through a Transformer encoder for multimodal classification.

The pose representation uses 67 landmarks:
- Body pose: 25 landmarks.
- Left hand: 21 landmarks.
- Right hand: 21 landmarks.
- Facial landmarks are excluded.

## Dataset

This project uses the ASL Citizen dataset.

Official dataset page: https://www.microsoft.com/en-us/research/project/asl-citizen/

The dataset is not included in this repository. Users must obtain their own authorized copy and comply with the applicable dataset license.

The current implementation supports two subsets:

| Subset | Training | Validation | Test |
|---|---:|---:|---:|
| ASL Citizen100 | 1,800 | 364 | 1,287 |
| ASL Citizen300 | 5,037 | 1,049 | 3,598 |

These counts correspond to the subsets generated by this implementation. Class selection is based on training-split frequency, with alphabetical tie-breaking. Official split assignments are preserved, and exact reproduction of the paper's class lists and dataset protocol is not claimed.

**Dataset videos, manifests, class lists, model checkpoints and restricted dataset-derived artifacts are not distributed in this repository.**

## ASL Citizen100 Evaluation

The three model components were evaluated on a common paired held-out test set of 1,283 samples.

| Model | Top-1 Accuracy | Top-5 Accuracy | Macro F1 |
|---|---:|---:|---:|
| Appearance | 25.72% | 59.24% | 24.88% |
| Pose | 33.36% | 66.17% | 32.85% |
| Multimodal Fusion | **45.36%** | **76.46%** | **44.66%** |

The fusion model improves Top-1 accuracy by 12.00 percentage points over the pose branch and 19.64 percentage points over the appearance branch.

Additional evaluation metrics, comparison figures and experiment metadata are available under `results/aslcitizen100/`.

These results are from the current implementation and should not be interpreted as reproducing the reference paper's reported results.

## Environment Setup

### Requirements

- Python 3.10
- Conda
- PyTorch and Torchvision
- CUDA-compatible NVIDIA GPU for GPU acceleration
- OpenCV
- MediaPipe
- NumPy
- Other dependencies listed in `requirements.txt`

The development environment was tested with Python 3.10, PyTorch 2.5.1 with CUDA 12.1 support, and an NVIDIA GeForce RTX 3050 Laptop GPU. Other hardware and software combinations may require adjustments.

### Installation

Clone the repository:

```bash
git clone https://github.com/Sonamkumari31/sign-language-recognition.git
cd sign-language-recognition
```

Create and activate the Conda environment:

```bash
conda env create -f environment.yml
conda activate slr
```

Install a compatible PyTorch and Torchvision build for your system using the official installation instructions:

https://pytorch.org/get-started/locally/

Install the remaining dependencies:

```bash
python -m pip install -r requirements.txt
```

Verify the environment:

```bash
python scripts/check_environment.py
```

A clean installation on another machine should be tested before claiming complete clone-and-run reproducibility.

## Dataset Setup and Preprocessing

Obtain an authorized ASL Citizen dataset copy and extract it locally.

Follow:

- `docs/dataset_setup.md` for dataset configuration and manifest generation.
- `docs/preprocessing.md` for RGB frame extraction, landmark extraction and LTI generation.
- `docs/ASLCitizen100.md` for the ASL Citizen100 experiment and evaluation details.

All dataset paths must be configured for the local machine. Dataset files must remain outside public version control.

## Inference Application

The Streamlit application provides an interface for testing ASL word predictions using the trained appearance, pose and fusion models.

Run from the repository root:

```bash
streamlit run app.py
```

The application requires locally available model checkpoints and the corresponding label map. These files are not included in the repository.

## Reproducibility and Research Practices

- Preserve official dataset split assignments.
- Generate class selections using training data only.
- Keep raw datasets and restricted derived artifacts out of version control.
- Record preprocessing parameters and experiment configurations.
- Evaluate models using a common held-out test subset when comparing modalities.
- Report Top-1 accuracy, Top-5 accuracy and macro-averaged metrics.
- Document implementation choices and deviations from the reference paper.
- Do not use held-out test data for model selection or tuning.
